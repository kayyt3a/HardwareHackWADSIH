# Offline voice message: steps and files

The message is generated once on your laptop, converted to a C array, compiled into the firmware, and played from flash whenever WiFi is down. It needs no network, no PSRAM allocation and no server.

Your firmware already plays raw 16 kHz, 16-bit, mono PCM through `writeSamples()`, so the offline clip uses the same format and the same output path.

## Steps

### 1. Write the message

Keep it under about 4 seconds, since it plays every time the pad is pressed offline. Something like:

> "No connection. Please move to a place with better WiFi, then try again."

### 2. Generate the audio with your existing TTS

From the `server` folder, with your `.env` set up:

```
cd server
python tts_openrouter.py "No connection. Please move to a place with better WiFi, then try again." offline_message.wav
```

This uses the same voice as the normal answers, so it won't sound like a different device. The file lands in `server/audio_output/`. Copy it to `firmware/assets/offline_message.wav`.

Did the all the following steps using that version of the generated message.

### 3. Add the converter script

Create `firmware/tools/wav_to_header.py`. It reuses `server/pcm.py` to guarantee 16 kHz mono 16-bit.

```python
"""
wav_to_header.py — turns a WAV into src/offline_message.h, a C array of
16 kHz mono 16-bit samples that firmware plays straight from flash.

Usage, from the firmware folder:
    python tools/wav_to_header.py assets/offline_message.wav
"""
import os
import sys

HERE = os.path.dirname(os.path.abspath(__file__))
sys.path.insert(0, os.path.join(HERE, "..", "..", "server"))
import pcm  # noqa: E402  (reuses the server's converter)

MAX_BYTES = 300_000  # ~9 s; keeps the app partition comfortable


def main() -> None:
    if len(sys.argv) < 2:
        print("Usage: python tools/wav_to_header.py <file.wav>")
        sys.exit(1)

    wav = open(sys.argv[1], "rb").read()
    data = pcm.wav_to_pcm(wav)   # forces 16 kHz / mono / 16-bit
    if len(data) > MAX_BYTES:
        print(f"{len(data)} bytes is too long (limit {MAX_BYTES}). Shorten the message.")
        sys.exit(1)

    samples = [int.from_bytes(data[i:i + 2], "little", signed=True)
               for i in range(0, len(data) - 1, 2)]

    out = os.path.normpath(os.path.join(HERE, "..", "src", "offline_message.h"))
    with open(out, "w") as f:
        f.write("// Generated by tools/wav_to_header.py — do not edit by hand.\n")
        f.write(f"// Source: {os.path.basename(sys.argv[1])}, "
                f"{len(samples) / pcm.TARGET_RATE:.1f}s\n")
        f.write("#pragma once\n#include <Arduino.h>\n\n")
        f.write(f"static const size_t OFFLINE_MSG_SAMPLES = {len(samples)};\n")
        f.write("static const int16_t OFFLINE_MSG[] PROGMEM = {\n")
        for i in range(0, len(samples), 16):
            f.write("  " + ",".join(str(s) for s in samples[i:i + 16]) + ",\n")
        f.write("};\n")
    print(f"Wrote {out}: {len(samples)} samples, {len(data)} bytes")


if __name__ == "__main__":
    main()
```

### 4. Generate the header

```
cd firmware
python tools/wav_to_header.py assets/offline_message.wav
```

This creates `firmware/src/offline_message.h`. It's about 100–130 KB of data, which is fine for the 8 MB flash.

### 5. Add a play-from-memory function to `audio_playback.cpp`

Append this at the bottom. It reuses `writeSamples()`, so the volume (`AUDIO_GAIN`) matches normal replies.

```cpp
// Plays samples that already live in memory/flash (e.g. the offline message).
// No download step, no PSRAM allocation.
void playPcmFromMemory(const int16_t *samples, size_t count) {
  if (!speakerReady) {
    Serial.println("[SPK] not initialised — call setupSpeaker() in setup()");
    return;
  }
  i2s_zero_dma_buffer(I2S_NUM_1);
  i2s_start(I2S_NUM_1);
  writeSamples(samples, count);
  delay(150);   // let the DMA drain so the tail isn't cut
  i2s_zero_dma_buffer(I2S_NUM_1);
  i2s_stop(I2S_NUM_1);
}
```

### 6. Hook it into `main.cpp`

**a) Include and declare** near the top, next to the other includes and the `playPcmStream` declaration:

```cpp
#include "offline_message.h"
void playPcmFromMemory(const int16_t *samples, size_t count);
```

**b) Check WiFi before recording.** Right now the device records the question, then discovers it's offline (and `ensureWiFi()` blocks about 10 s retrying). Put this at the very top of `captureAskAndSpeak()`, before `startWarmConnect()`:

```cpp
  if (WiFi.status() != WL_CONNECTED) {
    Serial.println("[NET] offline — playing stored message");
    playPcmFromMemory(OFFLINE_MSG, OFFLINE_MSG_SAMPLES);
    WiFi.begin(WIFI_SSID, WIFI_PASSWORD);   // non-blocking retry for the next press
    wifiConnected = false;
    return;
  }
```

**c) Cover "WiFi up but server unreachable".** In the `else` branch at the end (`Serial.printf("Server error: %d\n", httpCode);`), add:

```cpp
    if (httpCode <= 0) {   // no route / timeout, not an HTTP error
      playPcmFromMemory(OFFLINE_MSG, OFFLINE_MSG_SAMPLES);
    }
```

You can leave the existing `ensureWiFi()` block as a fallback. It will rarely be reached now.

### 7. Build, flash and test

1. Flash the normal environment (`seeed_xiao_esp32s3`).
2. Turn off your phone hotspot or router, or walk out of range.
3. Press the pad. You should hear the message immediately, and the serial monitor should show `[NET] offline — playing stored message`.
4. Turn WiFi back on, press again a few seconds later, and check normal operation resumes.
5. Also test the server-down case by stopping `uvicorn` with WiFi still on.

### 8. Commit

```
git add firmware/assets/offline_message.wav firmware/tools/wav_to_header.py firmware/src/offline_message.h firmware/src/audio_playback.cpp firmware/src/main.cpp
git commit -m "Offline voice message played from flash when WiFi/server unreachable"
```

## Notes

- **Volume:** `AUDIO_GAIN` is 0.06, so the offline message will be as quiet as normal replies. Check it's audible.
- **Changing the wording later:** re-run steps 2 and 4, then rebuild.
- **Stale files:** `firmware/src/mp3test.cpp` and `firmware/tools/mp3_to_header.py` are obsolete, so don't confuse the new script with the old MP3 one. Your `mp3test.cpp` says the tool can't delete files, so you can remove them by hand.
- **`offline_fallback.h`:** this stub is still unused (`OFFLINE_FALLBACK_ENABLED 0`). Once barcode decoding is added there, `handleOfflineFallback()` can call `playPcmFromMemory` too. It isn't needed for this feature.
- **Pitch:** this is a good line for the dignity slide. When the device can't help, it says so out loud and tells the wearer what to do, instead of staying silent.
